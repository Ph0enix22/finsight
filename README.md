# FinSight

Know before you pay.

A mobile-first money copilot for India's UPI generation — paste bank SMS or a statement, get a clean
ledger, a safe-to-spend number, a what-if simulator, and a chat copilot that only ever repeats numbers a
tool actually computed. Built for **Arthaton 2026** (AI for finance).

Work in progress — see the phase build log below for what's live.

## How to run

```bash
# backend (FastAPI, SQLite by default)
cd backend
uv run python -m uvicorn app.main:app --reload   # http://localhost:8000/api/health

# frontend (Vite + React)
cd frontend
npm install
npm run dev                                       # http://localhost:5173

# ml package tests
cd ml
uv run python -m pytest -q

# everything via Docker
docker-compose up
```

Copy `.env.example` to `.env` and fill in `LLM_API_KEY` for the copilot (Phase 5). Never commit `.env`.

## Data notice

All transaction data in this repo is **synthetic**, generated by `scripts/generate.py`. No real bank data,
account numbers, or personal financial information is collected, stored, or committed.

## Windows notes

Dev machines here run Windows App Control / Smart App Control, which blocks unsigned or low-reputation
compiled binaries (launcher `.exe`s and compiled Cython/C extension `.pyd` DLLs inside packages) with
`ImportError: DLL load failed ... An Application Control policy has blocked this file.` This shaped a few
dependency pins and how commands are run.

**Pinned because the latest release's compiled extension was blocked — older, better-established builds pass:**
| Package | Pinned range | Resolved | Reason |
|---|---|---|---|
| `pydantic` (→ `pydantic-core`) | `>=2.13,<2.14` | 2.13.5 (core 2.46.5) | `pydantic-core` 2.50.4's `_pydantic_core` DLL (from pydantic 2.14.3) was blocked |
| `sqlalchemy` | `>=2.0,<2.1` | 2.0.57 | SQLAlchemy 2.1.8 introduced a new Cython `_util_cy` extension that was blocked |
| `pandas` | `>=2,<3` | 2.3.3 | pandas 3.1.1's `pandas._libs.pandas_parser` DLL was blocked |
| `scikit-learn` | `>=1.5,<1.6` | 1.5.2 | 1.9.1's `_pairwise_distances_reduction._sorting` extension was blocked. This only triggers on deep imports (`sklearn.compose`, `sklearn.model_selection`, `sklearn.metrics`) — a shallow `import sklearn` passes fine, so the usual single-line smoke test missed it; check with the actual imports you need. |

**Passed at latest version, no pin needed:** `fastapi`, `uvicorn`, `numpy` (2.4.6), `scipy` (1.17.1),
`statsmodels` (0.15.0), `rapidfuzz` (3.14.6), `joblib` (1.6.0), `pdfplumber` (0.11.10, incl. its compiled
deps `pypdfium2`/`cryptography`/`pillow`).

**Fallback escape hatch (not currently needed):** if a future SQLAlchemy C-extension build gets blocked
again, set `DISABLE_SQLALCHEMY_CEXT_RUNTIME=1` to force pure-Python mode — note the name is
`DISABLE_SQLALCHEMY_CEXT_RUNTIME`, not the older `SQLALCHEMY_DISABLE_CEXTENSIONS`.

**Running Python tools:** never call `.venv\Scripts\*.exe` directly — launcher exes are blocked too.
Always go through `uv run python -m ...` (e.g. `uv run python -m uvicorn`, `uv run python -m pytest`,
`uv run python -m ruff`, `uv run python -m alembic`). `pre-commit` only works as `py -m pre_commit`.
Both `backend/` and `ml/` are pinned to Python 3.11 via `uv python pin 3.11` (the bare `py` launcher
here defaults to 3.14).

**gitleaks pre-commit hook:** the `gitleaks` repo's pre-commit hook is `language: golang` — pre-commit
tries to download its own Go toolchain and `go install` the binary from source, and that `go.EXE` gets
blocked too. `.pre-commit-config.yaml` instead points `gitleaks` at a `language: system` local hook that
shells out to an already-installed `gitleaks` binary. This means **`gitleaks` must be installed and on
PATH** (`winget install Gitleaks.Gitleaks`) for the hook to work at all — pre-commit won't fetch it for you
on this machine.
